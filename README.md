# 门店屏（SignageTV）

安卓电视上循环播放图片和视频的播放器。10 块屏以内的门店自用，**不做多用户的后台系统**：素材在电脑上统一做好推上去，屏自己来拉；临时要换的对着屏幕点一下扫码直传；不在店里的时候用网页后台改内容。

## 现在做到哪一步

| 步骤 | 状态 | 内容 |
|---|---|---|
| 第 1 步 | ✅ 完成 | 单机跑通：扫本地目录循环播放、全屏常亮、开机自启 |
| 第 2 步 | ✅ 完成 | 远端播放清单 + 素材增量同步 + 电脑端发布工具 |
| 第 3 步 | ✅ 完成 | 手机扫码上传：屏幕显示二维码，手机同 WiFi 扫码直接传图/视频；**页面上能删任何来源的素材、能看素材内容（缩略图 + 大图/视频预览）、能直接改服务器地址，还能给这个页面加访问码**；设了码之后，电视上点屏也得先输这个码才显示二维码 |
| 第 4 步 | 🔶 部分 | Kiosk 加固：播放看门狗 ✅、定时重扫 ✅、定时重启 ⬜、彻底封返回键 ⬜、切图消黑屏 ⬜ |
| 第 5 步 | ✅ 完成 | 网页后台：浏览器里管线上内容、传素材、调顺序、看内容、一键发布（**空清单也能发 = 下架全部**）、**页面上改访问码**、**十块屏的状态回传**（谁在线、在播哪一版、谁还没更新） |

> 第 5 步做的是**发布端**的升级——把第 2 步那个命令行工具变成网页，链路本身没动，
> 电视端一行代码都没改。见「六、用法 D：网页后台」。

## 素材从哪来：三条路，自动选

```
① 手机扫码上传  ← 优先级最高
   屏幕显示二维码 → 手机同 WiFi 扫码 → 选图/视频 → 直接传进电视
   传完立刻插播，排在最前面

② 远端清单（配了就用它）
   电视端每 5 分钟拉一次
   playlist.json ──► 比对 size / sha256 ──► 缺哪个下哪个（增量）
   ──► 按当前时间过滤时段 / 星期 ──► 播放

③ 本地目录（兜底）
   扫素材根目录下的 media/（含子目录），按文件名升序循环，每 15 秒重扫一次
```

**播放列表 = ① + （②或③）**。远端拿不到东西时自动退回本地目录，**屏不会黑**；远端拉失败还会用上一次缓存的清单继续播。

**要删素材**：点一下屏幕（设了访问码就先输一次码）扫码打开页面，下半部分列着上面三条路来的**全部**素材，每条标着出处。
**手机**传的和**本地**目录里的随手能删，十几秒内生效；**远端**那几条不让删——它们是电脑端清单同步下来的，
删了下一次同步又会下回来，要下架得改电脑端的清单（详见「五、用法 C」里的删除素材一节）。

## 一、编译

**双击 `build.bat`**，或者：

```bash
sh build.sh
```

产物是 `app\build\outputs\apk\debug\signage-<版本名>-<版本号>-debug.apk`，例如 `signage-0.3.9-12-debug.apk`。

**版本号只改一个地方**：`app/build.gradle.kts` 开头的 `appVersionCode` / `appVersionName`。改完重编，APK 文件名和包内记录的版本会一起变。

> 装到电视后想核对装的是哪一版：**点一下屏幕**（或按遥控器「确定」键）呼出二维码，卡片底部会显示 `门店屏 v0.3.9 (12)`。

### 不想用本机环境？让 GitHub 编

代码推上去之后，GitHub 会自动编出三样：**APK**、**网页后台 exe**、
**最小容器镜像**（Alpine，约 70MB，推到 GitHub Packages 可以直接 `docker pull`，
也附带群晖能导入的 tar.gz），
不需要本机装 JDK 和 Android SDK。打一个 `v` 开头的 tag 推上去，
还会自动生成 Release，产物谁都能直接下载：

```bash
git tag v0.3.9 && git push origin v0.3.9
```

公开仓库用这个不花钱。细节（在哪看结果、怎么固定签名、出问题怎么查）见
[docs/ci.md](docs/ci.md)。

### 编译环境（这台机器上已装好，可直接用）

| 组件 | 位置 | 说明 |
|---|---|---|
| JDK 17 | `D:\jdk17\jdk-17.0.20.1+1` | Temurin 完整版，**必须有 `jlink`** |
| Android SDK | `D:\android-sdk` | platform-34 / build-tools-34.0.0 / platform-tools，许可已接受 |
| Gradle 8.7 | `D:\gradle-8.7` | 依赖缓存放 `D:\gradle-home`，避免写满 C 盘 |
| adb | `D:\android-sdk\platform-tools\adb.exe` | |
| 逻辑测试台 | `D:\android-toolchain\uploadtest` | 没有真机时跑纯逻辑测试（游标、上传服务、目录扫描） |

> **踩过的坑**：PyCharm 自带的 JBR 是精简版 JDK，缺 `jlink.exe`，AGP 会在 `compileDebugJavaWithJavac` 阶段失败。必须用 `D:\jdk17` 那个完整 JDK。`build.bat` 里已经指好了。

## 二、装到电视/盒子

**支持 Android 5.0（API 21）及以上** —— 老电视和安卓盒子都能装。

### 方法一：U 盘（老电视首选）

Android 5.x / 6.x 的电视一般**不带网络调试**，`adb connect` 连不上，走 U 盘最省事：

1. 把 APK 拷到 U 盘根目录
2. U 盘插到电视上，用电视自带的**文件管理器**找到这个 APK
3. 点它安装。如果提示「禁止安装」，去 设置 → 安全 → 打开「允许未知来源」

### 方法二：adb（盒子支持网络调试时）

设置里打开「开发者选项」和「网络调试（ADB）」，确保跟电脑同一网段：

```bat
D:\android-sdk\platform-tools\adb.exe connect 192.168.1.50:5555
D:\android-sdk\platform-tools\adb.exe install -r app\build\outputs\apk\debug\signage-0.3.4-7-debug.apk
```

> APK 文件名带版本号，上面那行换成你实际编出来的名字。装新版直接 `install -r` 覆盖即可，**电视上的素材和配置不会丢**。

> 报「**解析软件包时出现问题**」只有两个常见原因，都踩过并已锁死：一是 **APK 要求的系统版本高于电视**（`sdkVersion` 必须 ≤ 电视的 API 级别），二是 **只签了 v2 签名**——Android 7.0 以下只认 v1。`app/build.gradle.kts` 里 `minSdk = 21` 和 `enableV1Signing = true` 就是为这两条立的规矩，**改之前先想清楚**。

## 三、用法 A：本地目录（不用联网，最简单）

素材放在**公共目录**下：

```
/sdcard/signage/media
```

```bash
adb push D:\素材\ /sdcard/signage/media/
```

也可以**直接插 U 盘**、或者用电视自带的文件管理器往这个目录里拷。这个目录是**公开的**，
任何文件管理器都翻得到，不像 `Android/data/` 下面那样被系统藏起来。

**播放顺序 = 文件名升序**，用 `01_`、`02_` 前缀控制，例如 `01_开业促销.mp4`、`02_新品海报.jpg`。

- **每 15 秒自动重扫一次目录**，新拷进去的素材十几秒内就上屏，不用重启、也不用等一轮播完。
- **子目录也会往下翻**（最多 4 层），排序按相对路径。有些电视自带的文件管理器拷文件时会顺手多建一层，
  所以这里特意做了递归——不然就会出现「文件明明放进去了，屏幕上却说没有素材」。
  也可以拿它按活动分批：建个「国庆活动」文件夹丢进去就行。
- 文件名以 `.` 开头的会被跳过（手机上传写到一半的临时文件就靠这个挡掉）。

> **素材根目录是"实测"出来的，不是写死的。** App 启动时按
> ① 公共目录 `/sdcard/signage/` → ② `Android/data/com.laodao.signage/files/` → ③ 内部私有目录
> 的顺序，**挨个往里写一个探针文件试试**，谁能写就用谁。
> 所以哪怕电视上 `Android/data` 那个目录写不进去（老电视真会这样，表现就是「手机上传来好几个、成功 0 个」），
> 也会自动退到还能用的地方，不至于一声不响地失败。
> **实际用的是哪一个，手机打开 `/status` 一看就知道**（见第六节）。
>
> 要跑在 Android 6.0～10.0 的机器上，首次启动会弹一次存储权限，点「允许」即可；
> 5.x（店里那台电视）在安装时就自动授予了，不弹窗。

## 四、用法 B：远端清单（10 家店同步）

### 4.1 先决定素材放哪儿

| 场景 | 方案 | 成本 |
|---|---|---|
| 10 块屏都在**同一家店** | 店里一台常开的电脑/NAS，起个静态 HTTP 服务 | 0 |
| 10 块屏**分散在不同店** | 对象存储（腾讯云 COS / 阿里云 OSS） | 每月几块钱 |

**局域网方案**（店里那台电脑上执行，让它常开）：

```bash
cd D:\signage-web
python -m http.server 8000
```

假设这台电脑的局域网 IP 是 `192.168.1.10`，那清单地址就是
`http://192.168.1.10:8000/playlist.json`。

> **如果那台电脑上跑着网页后台（`server/`），就不用在旁边另起一个 `http.server`**：
> 本地目录模式的网页后台自带这个出口，清单地址是
> `http://192.168.1.10:8600/playlist.json`，页面上那张「电视端填什么」卡片会直接
> 把它写出来（带复制按钮）。它和上面的做法是同一件事，只是少起一个进程、
> 顺带能在浏览器里改内容。注意电脑别睡、防火墙要放行这个端口，
> 详见 [server/README.md](server/README.md) 第五节。

**对象存储方案**：建一个存储桶，权限设成「公有读私有写」，拿到形如
`https://signage-1250000000.cos.ap-shanghai.myqcloud.com/` 的默认域名。

> 腾讯云 COS 的完整配置步骤（建桶、子账号密钥、防盗刷、常见坑）见 **[docs/cos-setup.md](docs/cos-setup.md)**。

### 4.2 在电脑上准备素材目录

```
D:\signage\media\
├── 01_门店形象.jpg
├── 02_秋季促销.jpg
├── 03_新品视频.mp4
├── 04_夜场活动.jpg
└── playlist.preset.json     ← 可选，控制播放顺序和时段
```

`playlist.preset.json` 是可选的。不写就按文件名的自然顺序播；写了就能指定顺序、
每张停留多久、几点到几点播、星期几播。样例见 `tools/playlist.preset.example.json`：

```json
{
  "defaults": { "imageDurationSec": 8, "muted": true },
  "items": [
    { "file": "01_门店形象.jpg" },
    { "file": "02_秋季促销.jpg", "durationSec": 10 },
    { "file": "03_新品视频.mp4" },
    { "file": "04_夜场活动.jpg", "startTime": "18:00", "endTime": "22:00" },
    { "file": "05_周末特惠.jpg", "days": [6, 7] }
  ]
}
```

> `days` 里 `1`=周一 … `7`=周日。

### 4.3 发布

```bat
cd signage-tv\tools

rem 局域网方案：发到那台电脑的共享目录
publish.bat --src "D:\signage\media" --target "local:D:\signage-web"

rem 对象存储方案（先设好环境变量，见 4.5）
publish.bat --src "D:\signage\media" --target "s3://signage-1250000000/signage"
```

> `publish.bat` 会自动用装好 boto3 的那个 Python，不用记路径，也不用 `pip install`。
> **在 cmd / PowerShell 里跑，Git Bash 跑不了 `.bat`**（这台机器的安全策略拦了 `cmd.exe`）。

它会：扫素材 → 算 sha256 → **只传变过的** → 生成 `playlist.json`。
清单一定最后才写，保证端侧不会拉到「有清单、没素材」的中间状态。

常用参数：

| 参数 | 作用 |
|---|---|
| `--playlist "playlist-{device}.json"` `--device "A店"` | 10 家店各自一份清单，共用一套素材 |
| `--prune` / `--no-prune` | 是否删掉远端已不在素材目录里的文件（默认开） |
| `--dry-run` | 只打印计划，不动任何文件 |
| `--no-hash` | 不算 sha256，发布更快（但同尺寸换内容检测不到） |
| `--unmuted` | 不静音 |

`--target` 只支持两种：`local:<目录>` 和 `s3://<bucket>/<前缀>`。

### 4.4 让盒子知道去哪儿拉

在盒子的这个路径放一个配置文件（**和素材同一个根目录，是公开的，文件管理器直接能改**）：

```
/sdcard/signage/signage-remote.json
```

> 具体落在哪个路径由 App 实测决定（见第三节），手机打开 `/status` 能看到实际位置。

内容（样例见 `tools/signage-remote.example.json`）：

```json
{
  "playlistUrl": "http://192.168.1.10:8000/playlist.json",
  "device": "",
  "refreshIntervalSec": 300,
  "prune": true,
  "assetBaseUrl": ""
}
```

| 字段 | 说明 |
|---|---|
| `playlistUrl` | 必填。清单地址。**这里没有值就退回本地目录模式** |
| `device` | 设备名，用来替换 `playlistUrl` 里的 `{device}` 占位，如 `playlist-{device}.json` |
| `refreshIntervalSec` | 多久拉一次，默认 300 秒（5 分钟） |
| `prune` | 是否清理盒子上已不在清单里的素材，默认 true |
| `assetBaseUrl` | 素材基址，留空则取清单所在目录 |

推上去：

```bash
adb push signage-remote.json /sdcard/signage/signage-remote.json
```

**不想开电脑也行**：扫屏幕上的二维码，上传页里有「**电脑端清单（服务器地址）**」这一栏，
填好点「保存并立即同步」就完事（见第五节）。10 台屏装同一个 APK，
在每台的手机页面上改一下设备名即可，**不用重新打包，也不用 adb**。

**10 台盒子用同一个 APK**：每台只改这个 json 里的 `device` 字段就行。

### 4.5 对象存储的环境变量

```bat
set SIGNAGE_S3_ENDPOINT=https://cos.ap-shanghai.myqcloud.com
set SIGNAGE_S3_REGION=ap-shanghai
set AWS_ACCESS_KEY_ID=子账号的SecretId
set AWS_SECRET_ACCESS_KEY=子账号的SecretKey
```

用**子账号**的密钥，别用主账号的——原因和建法见 [docs/cos-setup.md](docs/cos-setup.md) 第 3 节。
还需要 `pip install boto3`（只有用对象存储时才需要）。

### 4.6 验证

```bash
# 电脑上：清单能取到吗
curl http://192.168.1.10:8000/playlist.json

# 盒子上：看日志
adb logcat -s SignageTV
```

日志里会打印类似：

```
远端；清单 8 项，当前时段可播 6 项；下载 2 个 / 跳过 6 个 / 清理 1 个，共 12 MB
```

## 五、用法 C：手机扫码上传（临时换内容用这个）

**场景**：你在店里，临时想加一张今天的促销图，不想开电脑、不想找 U 盘。

1. **点一下屏幕任意位置**（触摸屏）；遥控器机型按**「确定」或「菜单」键**
2. **设过访问码的话，电视上先弹一层「需要访问码」** —— 输对了才显示二维码；
   通过后 **5 分钟内**再点屏幕不用重输（店员传一次素材往往要点好几次）
3. 二维码浮出来 → 手机连上**和电视同一个 WiFi**
4. 用相机或微信扫屏幕上的码 → 打开上传页（页面本身还要再输一次码，见下）
5. 选图片或视频 → 点「开始上传」
6. 传完电视**自动插播**；页面下半部分列着电视上**全部**素材，随手能删（见「删除素材」）
7. 想收起二维码：**再点一下屏幕**；不管它也行，两分钟后自己收

不用电脑、不用 U 盘、**不走任何云端服务**——手机和电视在同一个局域网里直连，店里的宽带断了也照样能用。

### 删除素材（二维码页面的下半部分）

页面下半部分不是只列"刚传的"，而是**电视上的全部素材**——三条路来的都在这儿，每条前面标着出处：

| 标签 | 是哪来的 | 能不能删 |
|---|---|---|
| **手机** | 扫二维码传上去的 | 能删，也能一键清空 |
| **本地** | U 盘 / 文件管理器拷进 `media/` 的 | 能删 |
| **远端** | 电脑端清单同步下来的 | **不给删**，要下架得改电脑端的清单 |

- 删掉后**十几秒内生效**，电视自动重排，不用重启、也不用等一轮播完。
- 删的正好是**正在播的那条**：电视停在原来的位置往下播，**不会跳回第一条重头开始**。
- 删的是别的素材：正在播的那条**不被打断**，视频不会闪一下重来。
- **远端那几条为什么不让删**：文件是电脑端清单同步下来的，删掉之后下一次同步（默认 5 分钟）
  又会自己下回来。看到"删了又自己回来了"比不给删更让人糊涂。要下架远端素材就改电脑端的清单——
  清单里没有的条目本来就不播了；端侧配置里把 `prune` 打开的话，本地文件也会被顺手清掉。
- 名字带 `.` 开头的（上传写到一半的临时文件）不会出现在列表里。

### 看素材内容（缩略图与预览）

列表每行左边是**缩略图**，点缩略图或文件名就能看：

- **图片**：直接看大图。
- **视频**：直接在手机上播，能拖进度条（电视端支持分段传输，`Range` 那套）。
- 底下有「上一条 / 下一条」连着翻，按 `Esc` 或点黑底关掉。

**为什么值得有**：传错一张图、或者某张图其实是坏的，等跑到店里对着电视才发现就晚了。
现在扫个码就能确认"电视上这条到底长什么样"。

两个要知道的：

- **缩略图是原图直接缩小的**，电视端不装图像库所以不做压缩。一屏三十张几 MB 的大图，
  首屏会慢几秒、也走几十 MB 流量（做了懒加载，滚到才拉）。
- **视频不生成首帧**（那要电视端转码），只显示一个 ▶ 标记，点开才真加载。

### 在手机上改服务器地址

远端清单的配置（清单地址、设备名、刷新间隔）**也能扫码在手机上改**，不用抱着电脑去店里 `adb push`：

1. 扫码打开上传页 → 往下拉到「**电脑端清单（服务器地址）**」
2. 填清单地址；**10 台屏可以共用一份地址**，在地址里写 `{device}` 占位，每台只改设备名
3. 先按「**先测一下能不能连上**」——它会回报清单有几项、版本号多少，
   **还会顺手戳一下第一条素材**，确认素材路径也是对的（"清单拉得到、素材却取不到"是最隐蔽的坑）
4. 没问题再按「**保存并立即同步**」——电视会**马上**去拉一次，不用等下一个刷新周期
5. 「**关掉远端，只用本地目录**」：删掉配置文件退回本地模式。清单和已同步的素材都留着

改的就是素材根目录下那份 `signage-remote.json`（U 盘照样能改同一份文件），
写的时候先落临时文件再改名，拔电也不会留下半截配置把电视卡成黑屏。

### 设访问码（不想让店里谁都能传）

上传页本身是**局域网里谁都能打开**的：同一个 WiFi 下，任何一台手机输个 IP 就能看素材、删素材、
改服务器地址。默认也是这样（不设就不拦人）。设一次之后，所有操作都要先输访问码：

手机上打开上传页 → 拉到「**访问码（保护这个上传页）**」：

- 填「新访问码」（至少 4 位，**中文也行**）+ 再输一遍 → 「**保存访问码**」。当时那台手机不用重登。
- 想撤掉：填上当前码 → 「**关掉访问码（局域网内谁都能用）**」。
- 改完之后，**别的手机上的登录立刻失效**，下次进来要输新码（登录状态本身能记 14 天）。

访问码存在**素材根目录**下的 `signage-upload.json`（跟 `signage-remote.json` 并排，U 盘可见）：

```json
{
  "code": "你的访问码",
  "note": "手机上传页的访问码。删掉这个文件就恢复成不需要访问码"
}
```

> **忘了访问码怎么办**：把 U 盘插到电视上，或者用电视自带的文件管理器，**删掉这个文件**，
> 页面就恢复成不用访问码。这也是当初把码放在公开目录、而不是 App 私有目录的原因——
> 放私有目录里就只能重装 APK 了。

几个设计上的取舍：

- **默认不设码**。店里就自己人、电视也不对外的话，多一道门只是天天给自己添麻烦。
- **访问码文件坏了当作没设**（读不出来就当没这道门）。宁可门是开的，也不能把自己锁在门外——
  锁住了连改都改不了。
- **凭证是访问码的 HMAC**，所以改码 = 把所有已登录的手机一次性踢掉，不需要另存一个密钥文件。
- 没登录时，数据接口一律回 401 且带 `needLogin`，页面据此弹登录层。**上传被拒时也会先把
  请求体读干净再回**，免得手机报「网络中断」，把「该输码了」伪装成网络故障。
- 电视端 `/status` 里也带一行访问码状态（`uploadCodeSet`），手机上打不开页面时先看那儿。
- **设了码，电视上也要过同一道门**：点屏（或遥控器「确定」/「菜单」）先弹「需要访问码」，
  输对了才显示二维码 —— 二维码就贴在店里这块屏上，谁走过都能扫，扫到就能删素材、
  改服务器地址、甚至把访问码关掉。通过后 **5 分钟内**再点不用重输；连错 5 次冷 60 秒，
  免得有人站在屏前一直试。用的是**同一个码**，不另设一套。
  **没设码时点屏直接出码**，跟以前完全一样。

### 触摸屏怎么用

- **点一下屏幕**就能呼出二维码（设了访问码就先输一次码），**再点一下收起**。
  触屏一体机不需要遥控器。
- **认证那一层上按钮能直接点**（会弹出输入法）；遥控器机型用数字键输码、按「确定」提交、
  按「返回」取消。
- 用的是「轻点」判定，**滑动、擦拭屏幕不会误弹**——有人在屏上蹭一下不会跳出二维码挡住广告。
- 触摸和遥控器**两种方式同时可用**，互不冲突。不想要触摸呼出，把 `Config.kt` 里
  `TOUCH_TAP_ENABLED` 改成 `false` 即可。

### 几个细节

- **上传的东西放在哪**：素材根目录下的 `manual/`（通常是 `/sdcard/signage/manual`），
  和本地目录 `media/`、远端目录 `remote/` **完全隔离**，谁也不会覆盖谁。
- **优先级最高**：手机传的内容永远排在播放列表最前面，传完立刻跳过去播。
- **和远端模式共存**：就算配了远端清单，手机传的东西照样生效，而且**不会被远端同步清掉**。
- **上传中不打断广告**：二维码是叠在画面上的浮层，底下的视频照常播。
- **没素材时会自动亮出来**：屏幕上一片空白（提示"还没有素材"）时，二维码自己也弹出来，
  不用你去记点哪里；**一旦有内容开始播，浮层会自动收掉**，不会挡着画面。
  设了访问码时，自动弹的是**认证那一层** —— 否则把素材删空就能白拿到二维码，这道门就白设了。
- **二维码大小按屏幕算**：边长 = 屏幕短边的 34%（320～1000 像素之间）。电视屏幕密度普遍
  偏低，写死 dp 会在屏上显小、手机扫不动，所以改成按实际像素算——**1080p 的屏上是 367px**。
- **端口**：默认 8080，被别的程序占用会自动往后试到 8091。二维码里的地址就是实际端口。
- **没连局域网时**：屏幕上直接写明「没有检测到局域网地址」，提醒你先接 WiFi 或网线。

### 两个必须知道的坑

1. **手机和电视必须在同一个网段**。电视插网线、手机连 WiFi 时，如果路由器把它们分到
   不同网段，就连不上。
2. **有些路由器开了「AP 隔离」或「访客网络隔离」**：同一个 WiFi 下的设备互相访问不了。
   表现是扫码后页面打不开、或者一直转圈。**把 AP 隔离关掉**，或者让手机连主 WiFi 而不是访客网络。

> 这个功能靠电视自己监听端口，所以**只在店里的局域网内可用**——这是刻意的：
> 不需要任何外部服务器，素材也不会跑到公网上。

## 六、用法 D：网页后台（不在店里也能改内容）

手机扫码上传管的是「**人在店里**、局域网、秒级插播」；网页后台管的是
「**人不在店里**、走公网、改正式内容」。

前者救急，后者排期。**两个是互补的，不冲突**——扫码传的东西优先级最高、
不受网页这边影响；网页改的是那份正式清单，电视最多 5 分钟后拉过去。

```
浏览器 ──① 打开网页──► 后台服务 ──② 签一张上传凭证──► 浏览器
   │                       │
   │                       └──③ 写清单（playlist.json）
   │
   └──④ 拿凭证直接把文件 PUT 到对象存储（不经过服务器）
```

- 素材**从浏览器直接进对象存储**，不经过服务器。传 500MB 的视频也不占服务器带宽。
- 服务只干三件事：发网页、签凭证、写清单。所以它很轻——一台最便宜的云服务器就够，
  甚至不需要装 Web 框架，有 `python3` 和 `boto3` 就能跑。
- 电视端**一行都不用改**，还是拉同一份清单。

### 6.1 先在本机试

不用配对象存储，用本地目录就能跑通：

```bash
cd signage-tv
PY=python            # 换成你自己的 python（要用对象存储的话得装了 boto3）

SIGNAGE_STORAGE="local:D:/signage-online" \
SIGNAGE_ADMIN_CODE="自己设一个访问码" \
"$PY" server/signage_admin.py --port 8600 --host 0.0.0.0
```

Windows 也可以双击 `server\start-server.bat`。然后打开 <http://127.0.0.1:8600/>。

**不想在那台电脑上装 Python**：双击 `server\build-exe.bat` 打一个
`signage-admin.exe` 出来，单文件约 27 MB，拷过去双击就能跑（配置写在 exe 旁边的
`signage-server.json` 里）。详见 [server/README.md](server/README.md) 第二节。

页面最下面有一张「**电视端填什么**」卡片，写着电视端该填的清单地址（带复制按钮）。

> 本地目录模式的网页后台**顺便就是那台"静态服务器"**：它免登录地把清单和素材发给电视，
> 所以这套东西不用另外起 `python -m http.server`。电视端地址填
> `http://这台电脑的局域网IP:8600/playlist.json`，别填 `127.0.0.1`（只有本机认得）。
> 电脑别睡、防火墙放行 8600。详见 [server/README.md](server/README.md) 第五节。

跑一遍自测（会建临时目录、打真实 HTTP 请求，不动你的数据）：

```bash
"$PY" server/selftest.py
```

### 6.2 放到云上

完整步骤（买服务器、环境变量、systemd 常驻、防火墙、**COS 跨域规则**、
排错表）写在 **`server/README.md`**，照着做就行。两件最容易漏的事先说：

1. **对象存储桶必须配跨域（CORS）规则**，允许你访问后台的那个来源发 `PUT`。
   不配的话浏览器直传一定失败，而且报错五花八门，看着像网络问题。
2. **`SIGNAGE_STORAGE` 的前缀必须和 `publish.py --target` 用的完全一样**，
   否则命令行发一套、网页发另一套，两边互相看不见。

**有群晖 NAS 的话，还有一条更省心的路**：把这个后台跑在 NAS 上（Container Manager
里起个容器就行）。**不用构建镜像、也不用装 Python** —— 服务端只用标准库，
拉个官方 python 镜像挂上代码就能跑。NAS 常年不关机，素材本来也存它上面，
比"另租服务器"或"店里电脑一直开着"都稳。

想连代码都不往 NAS 上放，就用 CI 打好的**最小镜像**（约 70MB，Alpine）：
NAS 上 `docker pull ghcr.io/binhe-cpu/signage-tv:latest` 直接拉，配一个
`docker-compose.min.yml` 就完事。这个包**是多架构的**（一个 tag 下挂着 amd64 和
arm64 两份），x86 的群晖和 ARM 的群晖拉同一个名字，自动挑对的。拉不通 ghcr.io
（国内网络常见）就去 Releases 下 tar.gz 导进去 —— 那条路 NAS 连网都不用通，
但**得按 NAS 的 CPU 挑一份**（`-amd64-` 还是 `-arm64-`）。
两种跑法的取舍见 [`server/README.md`](server/README.md) 第三节。

> 注意 `signage-admin.exe` 在群晖上没用（那是 Windows 程序），但**源码一行都不用改**。

### 6.3 页面上的几个设计取舍

- **「删除」是真的从线上删文件**。删掉的素材如果还在播放顺序里会一起被摘掉，
  清单同时重写——不然清单引用一个不存在的文件，电视会反复下载失败，看着像故障。
- **「移除」只是不播了**，文件还留在素材库里。分开是为了避免手滑删文件。
- **看素材内容也不经过服务器**（`GET /api/preview?file=...`）：对象存储模式下服务只回一个
  302，浏览器拿临时凭证直接去对象存储取图/取视频——服务照样不转发字节。
  本地目录模式则由服务直接读文件返回，**带 Range 支持**（视频拖进度条必须靠它，
  没有它浏览器只能从头播）。只服务图片和视频，清单文件这类读不出去。
- **缩略图是原图直接缩小的**，服务端不装图像库所以不做压缩。三十张几 MB 的大图
  一次铺出来首屏会慢几秒、也会走几十 MB 流量，看过的缓存一分钟。
  视频不取首帧（那要服务端转码），只给个播放标记，点开才真加载。
- **空清单能发布，但要自己确认一次**（= 把远端内容全部下架）。屏那边会退回播本地目录
  `media/`，**素材文件一个都不删**，重新加回来是瞬时的。
- **发布 = 写清单，没有"保存"中间态**。清单引用的素材必须都已在线上，
  否则整个发布中止并点名是哪个没传完。
- **`size` 由服务端按线上实际大小填**，不采信页面报的数——页面可能是错的。
- 网页和命令行**共用同一份清单生成逻辑**（`tools/signage_core.py`）。
  两边各写一套的话，改一处忘一处，生成的清单就不一致了，而端侧对不一致的表现
  只是"某些素材不更新"，极难排查。

### 6.4 改访问码

后台右上角「**安全设置**」→ 填当前访问码 + 新访问码（输两遍）→ 保存。

- 改完**其他设备上的登录立刻失效**（得用新码才进得来），**当前这台不用重输**。
- 访问码存在服务器上 `server/data/code.json`。**没设 `SIGNAGE_ADMIN_CODE` 时**，
  第一次启动会随机生成一个并**存进这个文件**——所以重启不变
  （老版本是每次重启换一个，每次都得翻日志找码）。
- 反过来，如果访问码是**从环境变量 / 命令行给的**，页面上就**改不了**，并且会明确告诉你
  去改哪个变量。环境变量是更高一级的来源，在页面上改了下次重启又变回去——
  那种"改了没用"比不让改更坏，所以直接不给你改。
- **忘了访问码**：删掉服务器上的 `server/data/code.json`，重启会重新生成一个并打在日志里。
- 这个后台**不允许把访问码清空**（它长期挂在公网上），要彻底重来就走上面那条删文件的路。

### 6.5 十块屏的状态回传（谁活着、在播哪一版）

屏每隔「拉清单的间隔」往后台报一次自己现在的状况，页面**最上面**那张「电视状态」卡片
显示每块屏：

| 显示什么 | 用处 |
| --- | --- |
| 名字、在线/离线、多久没心跳 | 一眼看出哪台掉线了（断网、拔电、进程被杀） |
| 版本、模式 | 确认十块屏装的是不是同一个版本 |
| 正在播第几条 / 共几条 + 文件名 | 「改了内容但屏上没变」时，看它到底卡在哪儿 |
| **清单版本号**（跟线上不一致会标「还是旧版」） | 最值钱的一条：谁还没更新上去，不用跑店里 |
| 素材数（手机 / 本地 / 远端） | 素材到底下下来了没 |
| 上次同步结果、上次播放出错 | 远端不通、某张图解码失败这类问题直接写在脸上 |

几个要紧的设定：

- **端侧一行都不用配**。上报地址是从**清单地址**同源推出来的（`http://你填的地址/api/report`），
  填过清单地址回传就自动有了。清单填的是对象存储桶的域名（那边没有接收接口）就不报。
- **想关掉**：在屏的素材根目录下 `signage-remote.json` 里加一行 `"reportUrl": "off"`。
  手机上保存服务器地址时这一行**会原样保留**，不会被冲掉。
- **时间一律以服务器为准**。老电视的系统时钟经常是错的（差几年的都见过），
  页面上的"多久没心跳"按服务器收到的时刻算，端侧报上来的时间只作参考。
- **离线判定**：超过「上报间隔 × 3」没心跳算离线，**最少给 15 分钟宽限**——
  间隔 60 秒的屏抖一下就标红的话，页面红成一片反而没人看了。
- **回传坏了不影响播放**。地址填错也只是自认失败，屏照播。连续失败 3 次后改成
  每 3 次机会试一次，不会一直白敲。手机上传页的「服务器地址」那里能看到这台屏往哪报、上次报成功没。
- **台账落盘**（`server/data/reports.json`），**服务重启不会丢**。重启一次就变成
  "一台设备都没有"的话，会让人以为全店的屏都掉了，白跑一趟店里。最多留 200 台，30 天没心跳的自动清掉。
- 上报接口**免登录**（十块屏没地方填访问码，换码时屏全挂店里）。
  要把这个端口放到公网时可以用 `SIGNAGE_REPORT_TOKEN` 加一道口令，但**端侧没有填口令的地方**，
  设了屏就静默报不上来（启动日志会警告）——除非将来端侧也支持填，否则别设。

## 七、出问题了怎么查

电视系统没有 adb，屏幕上也不显示日志。所以做了个**状态页**，用手机看：

1. 点一下屏幕，二维码浮出来，**二维码下面那行地址**就是电视的上传服务地址，形如 `http://192.168.1.5:8080/`
2. 手机浏览器打开这个地址，页面最下面有个「**查看播放状态**」按钮
3. 点它，能看到：

```
版本：门店屏 v0.3.8 (11)
模式：本地目录　触屏点击：开
上传地址：http://192.168.1.5:8080/

【播放】共 4 条，当前第 2 条：02_新品海报.jpg
　播放中：是（图片）　已播 3 秒
　连续失败：0
　上次错误：图片解码失败：xx.jpg

【存储】/sdcard/signage　公共目录（实测可写）
　· 可写　 /sdcard/signage
　· 可写　 /storage/emulated/0/Android/data/com.laodao.signage/files
　· 可写　 /data/user/0/com.laodao.signage/files

【本地目录 media】/sdcard/signage/media
  1. 01_开业促销.mp4  12.3 MB
  2. 02_新品海报.jpg  840 KB

【手机上传 manual】/sdcard/signage/manual
  （空）

【远端 remote】/sdcard/signage/remote/media
  （空）
```

对照着看，基本一眼能定位：

| 现象 | 看哪里 | 说明 |
|---|---|---|
| 传了/拷了不播 | 【播放】总条数 | 是 0 说明**目录里没扫到文件** → 看下面三个目录列表，核对路径和文件名 |
| 同上 | 目录列表 | 列出来的才是真被认到的。没有你的文件 → 路径不对，或扩展名不在支持范围 |
| 手机上传来好几个、成功 0 个 | 【存储】 | 说明落盘失败。看「可写」那一行：全不可写就是电视存储有问题，插张 SD 卡再试 |
| 电视上找不到素材目录 | 【存储】第一行 | 那就是实际用的根目录。显示"内部私有目录"说明没拿到存储权限，只能靠手机上传 |
| 屏幕提示"素材都无法播放" | 上次错误 | 一般是图片格式不认识或文件损坏 |
| 播着播着不动了 | 播放中 + 已播秒数 | 已播秒数巨大就是卡住了，看门狗 15 分钟会自动跳过 |
| 手机上删不掉某条 | 列表前的标签 | 标 **远端** 的删不掉是故意的（改电脑端清单下架）；**手机/本地**的删不掉，页面会写明原因，一般是只读或文件正被占用 |
| 点一下屏幕，电视上先要访问码，不记得了 | 电视上那层认证浮层 | 说明这台电视设过访问码。忘了就插 U 盘、或用电视文件管理器删掉素材根目录的 `signage-upload.json`，点屏就恢复成直接出码（浮层上也写着这句） |
| 手机打开上传页，先让输访问码 | 页面上「访问码」卡片 | 说明这台电视设过码。输一次就行，登录状态能记 14 天。忘了就把电视上的 `signage-upload.json` 删掉 |
| 网页后台进不去（访问码忘了） | 服务器上 `server/data/code.json` | 删掉它重启，会重新生成一个并打在启动日志里 |

**支持的格式**：图片 `jpg / jpeg / png / webp / bmp`；视频 `mp4 / mkv / webm / ts / mov / m4v / avi / 3gp`。
其它扩展名一律不认（比如 `.gif`、`.heic` 不在列表里）。

> 浏览器里直接打开 `http://电视IP:8080/status` 也行，看到的是同一份原始 JSON。

## 八、开机自启（按可靠性排序，前两条都要做）

1. **最稳 —— 把它设成「桌面」**：打开 `app/src/main/AndroidManifest.xml`，把 `HOME` 那段
   `intent-filter` 的注释取消掉，重新打包安装。然后在电视上**按 Home 键**（触屏一体机在
   `设置 → 主屏幕 / 默认应用` 里选），选「始终」用「门店屏」打开。系统开机后自己就会把
   播放界面拉起来，不依赖任何广播。
2. **必做 —— 加入自启动白名单**：电视 `设置` → `应用管理` → `门店屏` → 打开「自启动 / 允许后台运行」。
   国内品牌电视不加这一步，开机广播大概率收不到或被拦。
3. **补充 —— 开机广播**：已写在 `BootReceiver.kt`。Android 10 以后系统会拦截「后台启动界面」，
   原生系统上可能被静默丢弃，所以只是补充手段。

## 九、常改的参数

都在 `app/src/main/java/com/laodao/signage/Config.kt`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `IMAGE_DURATION_MS` | `8000` | 图片停留毫秒数（清单里写了 `durationSec` 的以清单为准） |
| `MUTED` | `true` | 是否静音 |
| `IMAGE_FIT_CENTER` | `true` | `true` 等比缩放留黑边；`false` 铺满屏幕会裁切 |
| `LOCAL_RESCAN_MS` | `15000` | 本地模式下多久重扫一次素材目录（新拷的立刻上屏） |
| `PLAY_WATCHDOG_MS` | `900000` | 一条内容播超过这么久就认为卡住，强制跳下一条（15 分钟） |
| `EMPTY_RETRY_MS` | `10000` | 全部素材都播不了时多久重试一次 |
| `DEFAULT_REFRESH_SEC` | `300` | 拉清单的默认间隔 |
| `HTTP_TIMEOUT_MS` | `15000` | 拉清单超时 |
| `DOWNLOAD_TIMEOUT_MS` | `120000` | 单个素材下载超时 |
| `UPLOAD_ENABLED` | `true` | 手机扫码上传总开关。关掉就不监听端口、不显示二维码 |
| `UPLOAD_PORT` | `8080` | 上传服务起始端口 |
| `UPLOAD_MAX_BYTES` | `512 MB` | 单个上传文件上限 |
| `QR_AUTO_HIDE_MS` | `120000` | 二维码浮层多久自动收起（触屏上要掏手机连 WiFi，留宽一点） |
| `AUTH_AUTO_HIDE_MS` | `120000` | 认证浮层多久自动收起（有人点开就走开，不能一直盖着广告） |
| `TOUCH_TAP_ENABLED` | `true` | 触摸屏：点屏幕呼出/收起二维码。关掉就只认遥控器按键 |
| `QR_SIZE_RATIO` | `0.34` | 二维码边长 = 屏幕短边 × 它。改大更好扫，改小不挡画面 |
| `QR_SIZE_MIN_PX` / `QR_SIZE_MAX_PX` | `320` / `1000` | 二维码边长的上下限（像素） |

「点屏先认证」那几个参数在 `UploadAuth.kt` 里（跟访问码本身放一起）：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `GRACE_MS` | `300000` | 认证通过后多久内再点屏不用重输（5 分钟） |
| `TRY_LIMIT` | `5` | 连错几次开始冷却 |
| `COOLDOWN_MS` | `60000` | 冷却多久（1 分钟） |

## 十、已知限制

- **图片与视频切换时可能闪一下黑**：现在靠切显隐实现，双图层预加载留到第 4 步一起做。
- **解码能力取决于电视**：老电视播 1080p 可能吃力，如果发现卡顿，素材统一压到 720p。
- **手机上传不校验内容**：只按扩展名判断是不是图片/视频，传进来的东西直接播。
  自己店里用没问题，**别把端口暴露到公网**。
- **缩略图走的是原图**：电视端不装图像库，所以缩略图是原图缩小显示，不生成真正的缩略图。
  一屏几十张几 MB 的大图，首屏会慢几秒、也走几十 MB 流量（有懒加载，滚到才拉）。
  视频也不生成首帧，只给个 ▶ 标记。真要省流量，就把素材压小一点。
- **改服务器地址要在店里**：那个设置在电视自己的页面上，只能连同一个 WiFi 时打开。
  不在店里想改地址，还是得 U 盘改 `signage-remote.json`，或者远程桌面进店里的电脑。
- **没有定时重启和崩溃自恢复**：播放看门狗有了，进程级的自恢复还在第 4 步。
- **返回键没封**：现在能退出到系统桌面，方便调试；第 4 步做 Kiosk 时再彻底封死。
- **清单不会自动发布**：素材换了要有人点一次发布（网页后台点一下，或跑 `publish.py`）。
  没做「改完自动生效」——发布这个动作留给人，是刻意的。
- **网页后台看不到"屏上正在播什么画面"**：状态回传只报"第几条 / 文件名"，不截屏。
  要真看画面得去店里，或者再加一路截图上报（代价大，暂时不做）。
